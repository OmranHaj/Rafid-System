# دليل تشغيل وتسليم RAFID MVP

## تجربة الدورة كاملة

1. شغّل `npm run demo` وافتح `http://127.0.0.1:3000`.
2. اختر «صاحب محل»، وقارن منتجين وأضف عرضًا من كل مورد.
3. افتح السلة، وأدخل `دمشق` وعنوانًا تجريبيًا. راجع الرسوم والمواعيد، وجرب اقتراح الخطة ومرجع التوفير قبل تطبيقها.
4. أكد الطلب: رئيسي وفرع مستقل لكل مورد.
5. من «المورد الأول»: اقبل وجهز واجعل الطلب جاهزًا، ثم حدده وأسنده لسائقه.
6. من «المورد الثاني»: جهز واطلب توصيل رافد. من «الإدارة»: حدد الطلب وأسنده لسائق رافد.
7. من حساب السائق: اقبل المهمة واستلم البضاعة ثم ابدأ التوصيل وأكد الوصول. استلم بضائع جميع طلبات الرحلة قبل بدء التوزيع.
8. افتح الطلب كمحل للحصول على رمز التسليم؛ أدخله كسائق وسجل النقد. الرمز لا يظهر للسائق أو المورد.
9. كمحل: أكد الاستلام والمبلغ وجرب التقييم وبلاغ نقص. من الإدارة سجل قرار المعالجة.
10. راجع التقارير وسجل الأحداث، وأعد تشغيل الخادم للتأكد من استمرار البيانات.

## نشر تجربة خاصة

الشروط: Node.js 24، قرص دائم، HTTPS وشهادة صحيحة وreverse proxy إلى localhost:3000، وكلمة مرور مدير عشوائية طويلة. لا تنشر `.env` أو `data` أو حسابات العرض.

```powershell
Copy-Item .env.example .env
# اضبط ADMIN_PASSWORD وPUBLIC_ORIGIN وSECURE_COOKIES=1 وDB_PATH جديد
node --env-file=.env server.js
```

استخدم مدير خدمات يعيد التشغيل. لحاوية Docker: اضبط `.env` ثم `docker compose up -d --build`. المنفذ مربوط بـlocalhost والوصول الخارجي عبر proxy HTTPS. volume `rafid-data` دائم؛ لا تحذفه عند تحديث الحاوية.

يفشل الخادم عند اكتشاف قاعدة العرض في الوضع الحقيقي. حساب المدير الأول `admin@rafid.local`، وكلمة مروره ADMIN_PASSWORD عند أول تشغيل فقط؛ تغيير المتغير لاحقًا لا يغيرها. لا توجد استعادة آلية في النسخة الحالية. سلّم حسابات الموردين والسائقين عبر قناة خاصة.

قبل الاستخدام الحقيقي: اعتمد العملة (ل.س صحيحة دون كسور)، الرسوم والحدود، المناطق والمواعيد، سعات المركبات، شروط الإلغاء والشكاوى، والتحصيل ومطابقة الإيصالات. قيم العرض ليست أسعار سوق مؤكدة.

## نسخة احتياطية واستعادة

ينشئ الأمر التالي نسخة متسقة من قاعدة تعمل باستخدام SQLite backup API مع فحص سلامة. لا تنسخ ملف SQLite وحده أثناء عمل WAL.

```powershell
node scripts/backup.js data/rafid.sqlite backups/rafid-2026-11-02.sqlite
```

يجب ألا يكون المسار النهائي موجودًا. احفظ النسخ على تخزين خاص خارج الخادم؛ تحتوي بيانات حسابات وعناوين وطلبات، ولا ترفعها إلى Git.

للاستعادة: أوقف الخادم، واحتفظ بنسخة مستقلة من ملفات القاعدة الحالية مع WAL/SHM، واستعد النسخة المتحققة إلى **مجلد جديد**. اضبط DB_PATH للمسار الجديد، وافتح الصحة والطلبات وقارن المجاميع. لا تستبدل قاعدة مفتوحة أو تخلط WAL من قاعدة قديمة.

## متابعة التجربة

- `/api/health` يتحقق من قاعدة البيانات، وليس الجاهزية التجارية.
- راقب الطلبات pending والتعثر. تنتهي الحجوزات بعد 24 ساعة ويُحرر المخزون عند طلب API مصادق عليه.
- قبل إعادة إسناد التعثر، وثّق أين عادت الحمولة. كل طلب في الرحلة مستقل.
- بعد خمس محاولات رمز خاطئة يتواصل السائق مع الإدارة، ويسجل التعذر. بعد مراجعة الحمولة تعيد الإدارة المحاولة، ويصدر رمز جديد عند استلام البضاعة مجددًا.
- طابق النقد المسجل مع تأكيد المحل والإيصال؛ التقرير ليس دفتر محاسبة أو تسوية.
- وزن مجهول يحتاج مراجعة الإدارة قبل الإسناد، دون ادعاء تحقق آلي كامل.

## حدود التحقق

اختبارات API وقاعدة البيانات تغطي الصلاحيات والتزامن والدورة الكاملة وإعادة التشغيل. فحص syntax يغطي الخادم والواجهة، وCI مهيأ لتكرار الاختبارات على Node 24. Docker مرفق لكن نجاح بنائه يحتاج بيئة يتوفر فيها Docker. لا توجد نتيجة اختبار حمل إنتاجي أو تجربة موردين فعليين ضمن هذا التسليم.
